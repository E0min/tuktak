# 예비창업패키지(예창패) MVP 기획안: TukTak 시뮬레이터

본 문서는 예비창업패키지 창업계획서 제출 및 발표를 위한 1차 MVP(Minimum Viable Product) 개발 계획을 정의합니다. 서비스 구현보다는 **'데이터 기반의 가시성'**과 **'알고리즘의 타당성 증명'**에 집중합니다.

## 1. 핵심 목표
- **시각적 증명:** 서울 지역 내 100개의 배차 수요를 지도상에 시각화하여 '합짐(혼적)'의 가능성을 시각적으로 제시.
- **수치적 증명:** Before(건별 배송) vs After(TukTak 합짐) 비교를 통해 효율성(거리 절감, 수익 증대)을 수치화.
- **기술적 타당성:** 네이버 네비게이션 API를 활용한 실제 경로 기반의 시뮬레이션 구현.

## 2. 데이터 설계 (Mock Data)
서울 지역 내 랜덤 배차 콜 생성기 (하루 100건 기준)

### 2.1 주문(Order) 속성
- **위치:** 서울 시내 랜덤 좌표 (상차지, 하차지).
- **시간:** 상차 가능 시간, 하차 희망 시간 (당일/익일 구분).
- **화물:** 
  - 종류: 가전, 가구, 매장 집기, 소형 사무실 집기 등.
  - 차종: **1톤(1T) 고정**.
- **운임:** Naver Navigation API에서 제공하는 실제 주행 거리를 기반으로 한 산정 모델 적용.

## 3. 기술 스택 및 연동
- **지도 API:** 네이버 지도(Naver Maps) API 및 네이게이션 SDK.
- **시각화:** 
  - 지도 위 100개 마커(상/하차지) 표시.
  - 합짐 루트별 경로(Polyline) 렌더링.
- **프론트엔드:** Next.js (App Router), Tailwind CSS, Framer Motion.

## 4. MVP 주요 화면 구성
1. **메인 대시보드:** 100개의 점(수요)이 찍힌 서울 지도.
2. **시뮬레이션 패널:** 
   - '시뮬레이션 실행' 버튼 클릭 시 알고리즘 작동.
   - 100개의 단독 배송이 몇 개의 '최적 합짐 루트'로 묶이는지 애니메이션으로 표현.
3. **KPI 리포트:**
   - 총 차량 운행 수 감소 (100대 -> N대).
   - 총 주행 거리 및 탄소 배출 절감량.
   - 기사당 기대 수익 변화 및 화주 비용 절감액.

- **Day 3:** 대시보드 UI 연동 및 예창패 발표용 수치 검증.
