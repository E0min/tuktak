# 제품 요구사항 정의서 (PRD_MVP_SIMULATOR.md)

| 프로젝트 | TukTak 시뮬레이터 MVP |
| :--- | :--- |
| 목적 | 예비창업패키지 사업성 증명 및 알고리즘 시각화 |
| 대상 | 예창패 심사위원, 잠재적 투자자, 운영팀 |

## 1. 프로젝트 배경 (Background)
국내 라스트마일 화물 운송 시장은 1톤 트럭의 공차율이 높고, 기사의 개별 운행으로 인한 비효율이 발생하고 있습니다. 'TukTak'은 데이터 기반의 합짐(혼적) 알고리즘을 통해 이 문제를 해결하고자 하며, 본 시뮬레이터는 그 효과를 실증하기 위한 도구입니다.

## 2. 제품 목표 (Objectives)
1. **문제의 가시화:** 서울 시내 100건의 배차 수요가 얼마나 밀집되어 있는지 시각적으로 확인.
2. **해결책의 제안:** 알고리즘이 100건을 어떻게 효율적인 N개의 루트로 묶는지 시뮬레이션.
3. **가 가치 증명:** 거리 절감 및 수익성 향상 수치를 통해 비즈니스 모델의 경제성 증명.

## 3. 핵심 기능 (Functional Requirements)
- **F-1: 랜덤 수요 생성:** 서울 지역 내 실시간 100건의 콜 데이터 생성.
- **F-2: 지도 시각화:** 네이버 지도를 활용한 100개 지점 마커 렌더링.
- **F-3: 알고리즘 엔진:** 하드 제약 조건(무게/부피/시간)을 준수하는 합짐 루트 도출.
- **F-4: 결과 비교:** '단독 배송' 대비 'TukTak 배송'의 거리/시간/수익 지표 비교 리포트.

## 4. 사용자 시나리오 (User Scenario)
1. 서울 지도 위에 100개의 배차 요청(상/하차지)이 랜덤하게 나타난다.
2. 각 배차를 따로 배송하는 경로를 표시한다.
3. '알고리즘 최적화' 버튼을 클릭한다.
4. 최적화된 합짐 경로(After)들이 표시된다.
5. 개별 배송 경로(Before)들이 최적화된 합짐 경로(After)들로 통합되는 과정이 표시된다.
6. 하단 대시보드에서 절감된 비용등의 KPI를 확인한다.(Before After 비교)

## 5. 성공 지표 (Acceptance Criteria)
- 네이버 지도 API가 오류 없이 로드되고 마커가 정상 표시되어야 함.
- 100개 데이터가 `MOCK_DATA_SPEC.md` 규격에 맞게 생성되어야 함.
- 합짐 결과가 시스템의 하드 제약 조건(1톤 용량 등)을 위반하지 않아야 함.
