# 알고리즘 명세 (ALGORITHM_SPEC.md)

이 문서는 화물 합짐(Bundling) 알고리즘의 논리적 구조와 수식 정의를 포함합니다.

## 1. 하드 제약 조건 (Hard Constraints)
다음 조건 중 하나라도 만족하지 못하면 합짐 후보군에서 즉시 제외합니다.
- **적재량:** $\sum{\text{물품 적재 부피}} \le \text{1톤 적재함}$, $\sum{\text{물품 중량}} \le 1,100\text{kg}$
- **시간 윈도우:** 상차 $A \to$ 상차 $B \to$ 하차 $A \to$ 하차 $B$ 순의 순차적 방문 가능성 보증. 상차와 하차 사이의 물리적 거리와 시간을 고려하여 실시간으로 경로를 최적화합니다.
- **마감 기한:** 모든 배송은 당일 21시까지 완료되어야 함.

## 2. 핵심 스코어링 함수 (Scoring Function)
후보 경로들 중에서 가장 효율적인 경로를 선정하기 위해 다음 점수를 산출합니다.
$$Score = w_1(\Delta \text{Distance}) + w_2(\Delta \text{Time}) + w_3(1 - \text{Load Factor})$$

- **$w_1$ (거리, 가중치 0.5):** 개별 배송 시 총 거리와 합짐 시 총 거리의 차이를 최소화합니다.
- **$w_2$ (시간, 가중치 0.3):** 불필요한 대기 시간이나 공차 주행 시간을 점수화하여 최소화합니다.
- **$w_3$ (적재율, 가중치 0.2):** 차량의 가용 공간을 최대한 활용하는 경로에 가점을 부여합니다.

## 3. 세부 평가 지표 (Detailed Metrics)
- **거리 증가율:** 개별 배송 거리의 총합 대비 합짐 경로의 총 거리 비율. (1.3배 초과 시 기각 권장)
- **공간 최적화:** 1톤 트럭의 적재함(평균 1.6m x 2.8m x 1.7m) 공간 대비 화물 부피 점유율.

## 4. 알고리즘 실행 프로세스
1. **데이터 수집:** 오더의 위경도, 부피, 무게, 희망 시간대 취합.
2. **최적화 전략 (Hybrid API Strategy):**
   - **Before (개별 배송):** 네이버 API를 호출하지 않고 **하버사인 직선 거리 × 1.3(서울 시내 보정 계수)**를 사용하여 거리와 운임을 즉시 산출합니다.
   - **After (합짐 배송):** 알고리즘으로 도출된 최종 최적 루트들에 대해서만 **네이버 Directions 5 API**를 호출하여 실제 주행 데이터(Path, Distance, Time)를 획득합니다.
3. **클러스터링 (Cluster-First):** 인접 지역(예: 강남구, 서초구) 오더들을 묶어 합짐 후보군 생성.
4. **경로 생성 (Route-Second):** 후보군 내에서 방문 순서를 조합하여 최단 경로 산출.
5. **검증 및 스코어링:** 하드 제약 조건 통과 여부 확인 후 최종 $Score$ 부여.
6. **최적안 확정:** 가장 낮은 $Score$를 가진 경로를 사용자에게 제안.
