# Git 컨벤션 (GIT_CONVENTIONS.md)

이 문서는 버전 관리 및 협업을 위한 Git 사용 규칙을 정의합니다.

## 1. 커밋 메시지 규칙
- **언어:** 모든 커밋 메시지는 **한국어**로 작성합니다.
- **형식:** `태그: 요약`

| 태그 | 목적 |
| :--- | :--- |
| `feat` | 새로운 기능의 추가 |
| `fix` | 버그 수정 |
| `docs` | 문서 수정 (README, DOCS/*.md 등) |
| `style` | 코드 스타일 변경 (포맷팅, 주석 등 코드 변경 없음) |
| `refactor` | 코드 리팩토링 |
| `chore` | 빌드 업무, 패키지 설정, 리셋 작업 등 |

**예시:** `feat: 하버사인 거리 계산 엔진 추가`

## 2. 작업 주기 및 푸시
- **단위 커밋:** 하나의 기능 단위나 의미 있는 작업이 완료될 때마다 커밋을 수행합니다.
- **즉시 푸시:** 커밋 후 지체 없이 원격 저장소(`origin`)에 `push`하여 상태를 동기화합니다.
- **히스토리 관리:** 의미 없는 커밋 메시지가 남지 않도록 주의합니다.
