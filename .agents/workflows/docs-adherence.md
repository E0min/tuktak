# 📜 Docs-Adherence Workflow (지침 준수 및 동기화)

이 워크플로우는 프로젝트의 모든 코드가 `DOCS/` 내의 지침을 엄격히 따르도록 보장하며, 개발 중 발생하는 변경 사항을 문서에 즉시 반영하여 '살아있는 문서(Living Docs)'를 유지하는 것을 목적으로 합니다.

## 1. 지침 준수 원칙 (Strict Adherence)
1.  **사전 검토:** 모든 구현 계획(Planning)은 `DOCS/` 디렉토리의 관련 명세(알고리즘, UI/UX, 컨벤션 등)를 바탕으로 수립되어야 합니다.
2.  **이탈 금지:** 코드 작성 시 `DOCS`에 정의된 규격이나 아키텍처를 임의로 변경하거나 생략할 수 없습니다.

## 2. 변경 및 이탈 시 프로세스 (Permission & Update)
개발 과정에서 기술적 한계, 더 나은 대안 발견 등으로 인해 `DOCS` 내용과 다르게 구현해야 하거나 문서를 수정해야 하는 경우 아래 절차를 반드시 따릅니다.

1.  **사전 설명 및 허가:** 
    -   변경이 필요한 이유와 예상되는 영향도를 사용자에게 상세히 설명합니다.
    -   `ask_user` 등을 통해 사용자의 명시적인 **허락**을 구합니다.
2.  **문서 선(先) 반영:** 
    -   허가를 받은 후, 실제 코드 수정 이전에 관련 `DOCS` 파일을 먼저 최신화합니다.
    -   수정 시 "왜(Why)" 이 내용이 바뀌었는지 의도를 포함합니다.
    -   **워크플로우 동기화:** 문서 수정 직후 [/workflow-sync](file:///Users/leeyoungmin/깃허브/tuktak/.agents/workflows/workflow-sync.md)를 실행하여 관련 워크플로우(예: pre-flight-check)의 메타데이터를 즉시 갱신합니다.
3.  **코드 구현:** 최신화된 `DOCS` 지침에 따라 코드를 작성합니다.

## 3. 핵심 체크리스트
- [ ] 현재 구현이 `DOCS`의 명세(예: `ALGORITHM_SPEC.md`)와 100% 일치하는가?
- [ ] `DOCS`와 다른 방향으로 개발할 경우 사용자에게 승인을 받았는가?
- [ ] 코드 변경에 따라 `SYSTEM_HANDOVER.md` 등 인수인계 문서가 업데이트되었는가?
