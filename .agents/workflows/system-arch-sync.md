# 🏗️ System-Arch-Sync Workflow (아키텍처 최신화)

이 워크플로우는 프로젝트의 물리적 구조, 데이터 흐름, 모듈 간의 관계가 변경될 때마다 `DOCS/05_System_Architecture/` 내의 산출물을 즉시 최신화하여 '살아있는 시스템 명세서'를 유지하는 것을 목적으로 합니다.

## 1. 실행 트리거 (Triggers)
- **디렉토리 구조 변경:** `src/` 내부의 폴더 구조가 추가, 삭제, 이동되었을 때.
- **인터페이스 및 타입 변경:** `src/types/` 내의 핵심 데이터 모델이 수정되었을 때.
- **비즈니스 로직 고도화:** `lib/engine/` 내 알고리즘의 핵심 단계나 로직이 변경되었을 때.
- **상태 관리 변경:** `store/` 또는 전역 상태 관리 방식이 변경되었을 때.

## 2. 작업 절차 (Process)
1.  **변화 감지:** 현재 구현된 코드와 기존 `05_System_Architecture` 문서 간의 차이점을 분석합니다.
2.  **문서 업데이트:**
    -   `SYSTEM_HANDOVER.md`: 변경된 디렉토리 책임, 새로운 모듈의 역할, 운영상의 특이사항을 반영합니다.
    -   `DATA_FLOW_DIAGRAM.md`: 데이터의 입출력 흐름, 컴포넌트 간의 통신 구조 변화를 텍스트나 다이어그램 형태로 갱신합니다.
3.  **검증:** 수정된 문서가 실제 코드의 구조 및 동작과 100% 일치하는지 자가 진단합니다.
4.  **커밋:** 문서 수정 사항을 해당 코드 변경 커밋에 포함하거나, `docs: 시스템 아키텍처 최신화` 메시지로 분리하여 커밋합니다.

## 3. 핵심 체크리스트
- [ ] 신규 생성된 폴더나 파일의 역할이 `SYSTEM_HANDOVER.md`에 명시되었는가?
- [ ] 데이터 흐름의 변화가 `DATA_FLOW_DIAGRAM.md`에 정확히 반영되었는가?
- [ ] 시스템 인수인계자가 코드 없이 이 문서만으로 전체 구조를 이해할 수 있는가?
