# 🔄 Doc-Sync Workflow (문서 최신화)

이 워크플로우는 기능 구현이나 아키텍처 변경 시 `DOCS/05_System_Architecture/` 내의 문서들을 최신 상태로 유지하기 위한 품질 보증 절차입니다.

## 1. 실행 조건
- 새로운 기능(`feat`)이 추가되거나 기존 로직이 수정(`refactor`, `fix`)될 때.
- 데이터 모델(`types`)이나 시스템 구조(`PROJECT_STRUCTURE.md`)에 변화가 생길 때.

## 2. 작업 절차
1.  **변경 사항 분석:** 구현된 코드의 핵심 로직, API 인터페이스, 데이터 흐름의 변화를 파악합니다.
2.  **문서 업데이트:**
    -   `SYSTEM_HANDOVER.md`: 시스템 개요, 모듈별 책임, 운영 주의사항 업데이트.
    -   `DATA_FLOW_DIAGRAM.md`: (필요 시) 데이터 흐름 및 상태 변화 로직 업데이트.
3.  **일관성 검증:** 업데이트된 문서 내용이 실제 구현된 코드와 일치하는지 최종 확인합니다.
4.  **커밋 지침:** 문서 업데이트는 해당 기능 구현 커밋에 포함하거나, 별도의 `docs: 시스템 인수인계서 최신화` 커밋으로 기록합니다.

## 3. 핵심 체크리스트
- [ ] 새로운 모듈이 `SYSTEM_HANDOVER.md`의 아키텍처 섹션에 반영되었는가?
- [ ] 변경된 데이터 스키마가 문서에 명시되었는가?
- [ ] 인수인계자가 별도의 코드 분석 없이도 시스템 구조를 파악할 수 있는가?
