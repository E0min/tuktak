# 📑 Handover-Sync Workflow (인수인계 및 상세 설계 최신화)

이 워크플로우는 프로젝트의 핵심 로직이나 시스템 구조가 변경될 때마다 `DOCS/05_System_Architecture/` 내의 문서를 Mermaid 다이어그램과 상세한 설명을 포함하여 최신 상태로 유지하는 것을 목적으로 합니다.

## 1. 실행 트리거 (Triggers)
- **핵심 로직 변경:** `src/lib/engine/` 또는 `src/features/` 내의 주요 알고리즘 및 비즈니스 로직이 수정되었을 때.
- **데이터 흐름 변경:** `src/store/` 또는 API 연동 방식 등 데이터의 입출력 및 상태 관리 흐름이 변경되었을 때.
- **아키텍처 변경:** 폴더 구조의 대대적인 개편이나 새로운 핵심 모듈이 추가되었을 때.

## 2. 작업 절차 (Process)
1.  **코드 분석:** 변경된 코드의 논리적 흐름, 모듈 간의 의존성, 데이터 전처리 및 결과 산출 과정을 심층 분석합니다.
2.  **문서 업데이트 (`SYSTEM_HANDOVER.md`):**
    -   변경된 모듈의 책임과 동작 방식을 텍스트로 상세히 기술합니다.
    -   변경 전후의 논리적 차이점과 운영 시 주의사항을 업데이트합니다.
3.  **다이어그램 업데이트 (`DATA_FLOW_DIAGRAM.md`):**
    -   **Mermaid**를 사용하여 변경된 시스템 아키텍처나 데이터 흐름을 시각화합니다 (Flowchart, Sequence Diagram, Class Diagram 등 적절한 형식 활용).
    -   복잡한 로직의 경우 단계별 처리 과정을 다이어그램으로 명시합니다.
4.  **검증:** 작성된 다이어그램과 설명이 실제 구현된 코드의 동작과 100% 일치하는지 확인합니다.
5.  **커밋:** 문서 수정 사항을 해당 코드 변경 커밋에 포함하거나, `docs: 시스템 인수인계서 및 다이어그램 최신화` 메시지로 커밋합니다.

## 3. 핵심 체크리스트
- [ ] 변경된 로직을 설명하는 **Mermaid 다이어그램**이 포함되거나 갱신되었는가?
- [ ] `SYSTEM_HANDOVER.md`에 변경된 모듈의 책임이 명확히 기술되었는가?
- [ ] 인수인계자가 코드 없이 문서와 다이어그램만으로 로직을 완전히 이해할 수 있는가?
- [ ] 다이어그램의 문법이 정확하며 렌더링에 문제가 없는가?
